# Интеграция GitHub

Нужен Node.js 18 или новее. Дополнительные пакеты не нужны: используются встроенные модули и `fetch`.

## Как получить токен

1. На GitHub откройте **Settings → Developer settings → Personal access tokens**.
2. Создайте **Fine-grained token**, выберите аккаунт, срок действия и нужные репозитории. Скопируйте токен сразу: позже GitHub его не покажет.
3. В файле `.env` в этой же папке, рядом с `github-client.js`, укажите `GITHUB_TOKEN=ваш_токен` без квадратных скобок и кавычек.

Файл `.env` добавлен в `.gitignore`, поэтому Git не должен включать его в новые коммиты. Не публикуйте токен и не отправляйте `.env` другим людям. Если токен уже оказался в публичном месте, отзовите его на GitHub и создайте новый.

## Разрешения токена

- Для списка репозиториев: доступ к выбранным репозиториям; для приватных репозиториев нужен соответствующий доступ. У fine-grained token разрешение **Metadata: Read** предоставляется автоматически.
- Для чтения `README.md` и других файлов: **Contents: Read**.
- Для создания issue: **Issues: Read and write** в целевом репозитории; в репозитории должны быть включены Issues.

Если используете классический personal access token, для приватных репозиториев обычно нужен scope `repo`, а для публичных операций достаточно `public_repo`. Выдавайте токену только необходимые права.

## Запуск примеров

Откройте терминал в папке проекта и запустите:

```powershell
node github-examples.js
node github-examples.js check
node github-examples.js repos
node github-examples.js readme ВЛАДЕЛЕЦ РЕПОЗИТОРИЙ
node github-examples.js issue ВЛАДЕЛЕЦ РЕПОЗИТОРИЙ
```

Обычный запуск проверяет токен, выводит все доступные репозитории и пытается прочитать `README.md` первого репозитория. Команда `issue` **создаёт настоящую тестовую issue** в указанном репозитории. Подставьте реальные имя владельца и имя репозитория.

## Методы `GitHubClient`

- `new GitHubClient()` читает токен из `.env` и проверяет его наличие и формат. Реальный доступ проверяется первым запросом к GitHub API.
- `getMyRepos()` получает все страницы списка доступных репозиториев, выводит их в консоль и возвращает массив.
- `getFileContent(owner, repo, path)` выводит и возвращает текст файла в кодировке UTF-8.
- `createIssue(owner, repo, title, body)` создаёт issue, выводит её номер и ссылку, возвращает ответ GitHub API.

При ошибке методы сообщают причину в консоли и выбрасывают исключение. Для своих сценариев оборачивайте вызовы в `try/catch`.
